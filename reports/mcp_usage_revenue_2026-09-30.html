MCP usage & revenue, last 30 days

Blocksize on mcp.blocksize.info, 30 Aug to 28 Sep 2026 (UTC), test traffic excluded. Every figure comes from two production stats snapshots, not a live query. Daily series join the 30-day snapshot (to 25 Sep, 23:00) with the 7-day snapshot (to 29 Sep, 00:07). 29 and 30 Sep are not included yet.

In short. MCP tool calls rose sharply: in the second half of the window than the first, peaking at 899 on 21 Sep. Revenue is still tiny. All of it came from direct x402 pay-per-call on the HTTP API, and 75 of the 92 paid calls fell on 14–17 Sep. None of the marketplaces (Pay.sh, Smithery, Glama, x402scan) has revenue that can be traced back to it. The MCP server is free and read-only, so MCP usage only turns into money when an agent follows the x402 link it returns.

Caveats

  • Not live. This was built from the stored production snapshots. The auto-mode permission policy blocked a fresh read-only query over SSH in this session, so 29–30 Sep are missing.
  • Marketplace-side numbers are missing. No external metrics feed is configured (platforms_configured = []). Smithery-hosted runs, Pay.sh catalog views and Glama install counts are not in this data, and none of their public pages shows usage counts.
  • No MCP tool calls in the authenticated connectors. The Claude, Cursor and ChatGPT connectors recorded only transport requests (118 in total) and gave out no free-tier grants.
  • The spikes have no per-client breakdown. The snapshot has daily totals only, so the MCP surge on 19–22 Sep and the paid cluster on 14–17 Sep can't be split by client here. Check whether the 14–17 Sep payments came from your own test wallets.
  • Test and smoke traffic is excluded: 5,433 events in the 30-day snapshot.
